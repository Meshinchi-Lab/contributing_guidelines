RMS Gene Explorer Shiny App on sp-alphafold-ws

Author

Jenny L. Smith

TipOverview

The rms_gene_explorer Shiny app allows exploration of gene expression across rhabdomyosarcoma (RMS) tumors, cell lines, and normal tissue cohorts used for RMS CAR T target discovery.

These steps run the app as a Docker container on the DELL Ubuntu PC (sp-alphafold-ws), either with a single docker run command (Quickstart) or as an always-on systemd service (systemd Deployment). The full instructions are in the repository deployment README.

The repository is private, so the links on this page only work for members of the lab github organization.

ImportantData governance

The app serves controlled-access PCGP data (dbGaP phs000720) and pre-publication OPBG data. Keep it bound to 127.0.0.1 and connect over an SSH tunnel. Do not deploy it to shinyapps.io or package it with shinylive.

See Data governance in the repository README.

1 Quickstart

The input data files (the expression store) are saved under 0003_ngs_processed_data on the network drive (see Data Management), so there is nothing to build. Login to sp-alphafold-ws using your username and password.

If the systemd service is already running on the host (systemctl is-active rms-gene-explorer prints “active”), skip to step 3.

  1. Clone the repository (first time only). The Docker image contains R and the package dependencies, and the app code is read from the repository.
cd $HOME/github_repos
gh repo clone Meshinchi-Lab/2026-09-25_RNAseq_RMS_targets
cd 2026-09-25_RNAseq_RMS_targets
mkdir -p store    # mount point for the input data
  1. Copy and paste the docker run command from inside the repository to launch the app. Docker pulls the image on the first run (see Get the Docker Image if the pull is denied).
DATA="/mnt/network_drives/storage-bioinfo_labq/0003_ngs_processed_data/locatelli_f/RMS/2026-09-25_RNAseq_RMS_targets"
STORE_DIR="$DATA/store"

docker run --rm \
    -v "$PWD":"$PWD" \
    -v "$STORE_DIR":"$PWD/store":ro \
    -w "$PWD" \
    -p 127.0.0.1:3838:3838 \
    ghcr.io/meshinchi-lab/rms-gene-explorer:4.5.3
NotePorts

If you recieve an error, “Bind for 127.0.0.1:3838 failed: port is already allocated”, run the command without the port specified.

docker run --rm -v "$PWD":"$PWD" -v "$STORE_DIR":"$PWD/store":ro -w "$PWD" ghcr.io/meshinchi-lab/rms-gene-explorer:4.5.3

  1. Open a web browser on sp-alphafold-ws and enter the URL http://localhost:3838.

Press Ctrl+C in the terminal to stop the app. To open the app from another computer, see Open the App.

2 systemd Deployment

Run the app as a shared, always-on service that starts on boot and restarts automatically, so lab members can open it without launching it themselves. You will need sudo access, and Docker must be running.

docker --version
systemctl is-active docker.service    # should print "active"

2.1 Clone the Repository and Copy the Store

Clone the repository, if you have not already done so in the Quickstart.

cd $HOME/github_repos
gh repo clone Meshinchi-Lab/2026-09-25_RNAseq_RMS_targets
cd 2026-09-25_RNAseq_RMS_targets

The service reads the input data from store/ inside the repository. Copy it from 0003_ngs_processed_data, using the same STORE_DIR as the Quickstart.

rsync -a "${STORE_DIR:?}"/ store/

To rebuild the store from the source data instead, see Build the store.

2.2 Get the Docker Image

Pull the published image.

docker pull ghcr.io/meshinchi-lab/rms-gene-explorer:4.5.3

If the pull is denied, either log in to the GitHub Container registry or build the image from the repository Dockerfile with the same tag.

docker build -t ghcr.io/meshinchi-lab/rms-gene-explorer:4.5.3 .

2.3 Install the systemd Service

Note

The service runs one shared copy of the app on port 3838 for the whole host. Check that it is not already installed with systemctl status rms-gene-explorer before continuing.

  1. Copy the environment file and set APP_DIR to your repository path.

APP_DIR must be a literal absolute path, because systemd does not expand $HOME or ~. Run these commands from inside the repository so that $PWD is filled in by the shell.

sudo install -m 0644 deploy/rms-gene-explorer.env.example /etc/rms-gene-explorer.env
sudo sed -i "s|^APP_DIR=.*|APP_DIR=$PWD|" /etc/rms-gene-explorer.env
grep APP_DIR /etc/rms-gene-explorer.env
  1. Install and start the service unit.
sudo install -m 0644 deploy/rms-gene-explorer.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now rms-gene-explorer.service
  1. Check that the app is running.
systemctl status rms-gene-explorer.service
curl -so /dev/null -w '%{http_code}\n' http://127.0.0.1:3838/   # expect 200

2.4 Open the App

On sp-alphafold-ws, open a web browser and enter the URL http://localhost:3838.

From your own computer, open an SSH tunnel to the host first. Use the host alias from your ~/.ssh/config if it differs.

ssh -N -L 3838:127.0.0.1:3838 YOUR_USER@sp-alphafold-ws

Then open http://localhost:3838 in a web browser. If you are connected with VS Code remote-ssh, you can instead forward port 3838 from the PORTS tab.

2.5 Update and Restart

Task Command
Restart after a code change (git pull) sudo systemctl restart rms-gene-explorer
Restart after the store is updated rsync -a --delete "${STORE_DIR:?}"/ store/ && sudo systemctl restart rms-gene-explorer
Restart after a new image docker pull ghcr.io/meshinchi-lab/rms-gene-explorer:4.5.3 && sudo systemctl restart rms-gene-explorer
Follow the logs journalctl -u rms-gene-explorer -f
Stop and disable sudo systemctl disable --now rms-gene-explorer
